# MCP instructions & tool descriptions — host limits and format recipe

What the MCP `instructions` and `Tool.description` fields actually are, the
host-side truncation that governs them, and the evidence-backed format tilth's
prompts follow. Evidence base:
`.cheese/research/mcp-instructions-tool-descriptions/` (full citations).

## The 2KB truncation (the gotcha)

Claude Code truncates MCP **server instructions at 2,048 chars per server**
and **tool descriptions at 2,048 chars each** — character-based, not
configurable, documented at code.claude.com/docs/en/mcp.md ("keep them
concise... put critical details near the start"). Discovered 2026-08-02:
tilth's composed instructions (runtime overview preamble + mcp-base.md +
mcp-edit.md) ran 8,698 chars, so Claude Code agents saw only through line 14
of mcp-base.md — **no per-tool section was visible**. This explained the
claude-side adoption gaps in [usage-analytics-2026-07](usage-analytics-2026-07.md)
(diff 7 claude vs 194 codex calls; grok target-less misuse; deps at 12 calls
vs 19:1 manual blast-radius work): a month of claude data was generated by
agents seeing ~25% of the manual. Codex/omp render instructions unclipped
(no confirmed field limit; Codex truncates tool *results*, openai/codex#6426).

Corollary: **error messages never truncate** — failure-time teaching errors
(the PR #146-#149 idiom) are the only guaranteed-delivery channel.

## What the spec says

`InitializeResult.instructions` and `Tool.description` are optional, untyped
"hints" that clients "MAY" add to the system prompt — no protocol-level
length rule; all limits are host policy. The ecosystem overloads
`instructions` as a de-facto system prompt because MCP has no native system
prompt primitive (modelcontextprotocol discussion #1137).

## Format recipe (evidence-backed)

Server instructions, ≤2,048 chars, in order:

1. **Identity + replacement claim first** — word 1 matters; clients may
   inject verbatim into the system prompt.
2. **Route-by-question inventory** — one line per tool: the question it
   answers, a worked example call, and a DO NOT naming the shell/builtin
   habit it replaces ("DO NOT" outperforms "IMPORTANT" for weak models —
   tilth haiku finding).
3. **Worked examples beat prose**: missing examples was the single
   highest-impact defect in an empirical six-component decomposition of tool
   descriptions (−30.5pp task success, arXiv:2602.14878).
4. Cut everything else — length proportional to complexity, don't fill the
   budget.

Tool descriptions, each ≤2,048 chars (shorter is better): purpose sentence →
"use when X, not when Y" → one example call. **Parameter semantics go in the
JSON Schema property `description` fields** — a spec-sanctioned channel not
subject to the prose truncation — never restated in description prose.
Anthropic's framing: write for "a new hire"; unambiguous param names; treat
descriptions as prompt-engineered artifacts and iterate against real
transcripts (anthropic.com/engineering/writing-tools-for-agents).

## tilth-specific application

- One complete instructions file per mode, chosen by the server's `--edit`
  param — no concatenation, each file independently ≤2,048 chars, byte-locked.
- The runtime overview preamble (`fingerprint()`, src/overview.rs) was
  dropped from MCP instructions 2026-08-02: unlabeled provenance, bound to
  the server's launch dir (wrong tree under worktrees — see
  [mcp-cwd-root-binding](mcp-cwd-root-binding.md)), stale after initialize.
  The CLI `tilth overview` command keeps the feature.
- A truncation-guard test asserts the first 2,048 chars of the served
  instructions contain every critical span, in both modes, so "below the
  fold" fails CI instead of silently shipping.
